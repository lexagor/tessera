# Reviewer Acceptance Evidence

**Status:** evidence template. No external reviewer has accepted a Tessera pack yet.

## Acceptance event

Record, with the reviewer's consent:

- Reviewer role and organization type (redact names if needed).
- Action/tool, policy, and environment scope reviewed.
- Evidence pack ID, generation date, archive SHA-256, and verifier command/output.
- Which controls/questions the reviewer mapped and whether the pack answered them.
- Gaps found, remediation, and whether the reviewer would accept a follow-up pack.
- Time to review and any offline verification issues.
- Signed/dated acceptance note or email; do not paraphrase into a stronger claim.

## Minimum artifact set

1. Signed receipt(s) and chain verification result.
2. Evidence pack summary + reviewer report + archive checksum.
3. Verification command and expected signer.
4. The reviewer's question list and Tessera's mapping.
5. Limitations shown to the reviewer (caller-asserted vs broker-observed, no certification).

## Claim rules

- “Reviewer reviewed” is not “reviewer certified” or “audit passed.”
- “Evidence pack accepted for this action” is not a company-wide SOC 2 opinion.
- Do not publish a customer/reviewer name without written consent.
- If acceptance is conditional, state the conditions and open gaps.

Until this file is populated with a real event, use “design-partner evidence in progress.”
